# 👑 Accounting Core Skill — المحرك المحاسبي القياسي المعتمد

هذه المهارة تمنح الوكيل المعرفة التخصصية والقواعد الصارمة لإدارة وبرمجة وصيانة المحرك المحاسبي المتكامل في النظام وفق معايير المحاسبة المالية المعتمدة (GAAP / IFRS).

---

## 1. 🎯 متى يتم تشغيل المهارة (Activation Triggers)
يجب تفعيل واستدعاء هذه المهارة تلقائياً في الحالات التالية:
- التعامل مع أي كود، دالة، أو استعلام يتعامل مع المعاملات المالية، السندات (سند قبض، سند صرف)، أو الفواتير.
- إنشاء، تعديل، أو تدقيق قيود اليومية المحاسبية (journal_entries / journal_entry_lines).
- إضافة أو تعديل شجرة الحسابات (chart_of_accounts / ccounts).
- احتساب أرصدة الحسابات أو استخراج القوائم المالية (ميزان المراجعة، قائمة الدخل، الميزانية العمومية، دفتر الأستاذ العام).
- معالجة فروقات العملات، الدفعات المقدمة، العرابين، الديون، أو مستحقات الموردين.
- إقفال الفترات المالية (Financial Period Closing) أو تسويات الجرد ومراكز التكلفة.

---

## 2. 🚫 متى يمنع تشغيل المهارة (When NOT to Activate)
- المهام المتعلقة بالتصميم الجرافيكي الصرف لواجهة المستخدم (CSS / Tailwind styling) التي لا تمس الحسابات.
- تعديل نصوص أو ترجمات الواجهة العامة غير المرتبطة بمفاهيم محاسبية.
- مهام إدارة مخزن الأقمشة الصرفة (قص، حجز مقاسات) طالما لم تتضمن قيد تكلفة أو تقييم مالي.

---

## 3. 🏛️ المفاهيم المحاسبية الأساسية التي تتقنها المهارة

### 1. نظام القيد المزدوج (Double-Entry Bookkeeping)
كل عملية مالية تؤثر على طرفين على الأقل: طرف مدين (Debit) وطرف دائن (Credit).
\sum \text{Debit} = \sum \text{Credit}

### 2. طبيعة الحسابات (Account Natures & Normal Balances)
| تصنيف الحساب (Category) | الطبيعة الافتراضية | الزيادة (+) | النقصان (-) | رقم المستوى الأول |
| :--- | :--- | :--- | :--- | :--- |
| **الأصول (Assets)** | مدين (Debit) | مدين (Debit) | دائن (Credit) | 1 |
| **الخصوم / الالتزامات (Liabilities)** | دائن (Credit) | دائن (Credit) | مدين (Debit) | 2 |
| **حقوق الملكية (Equity)** | دائن (Credit) | دائن (Credit) | مدين (Debit) | 3 |
| **الإيرادات (Revenues)** | دائن (Credit) | دائن (Credit) | مدين (Debit) | 4 |
| **المصروفات (Expenses)** | مدين (Debit) | مدين (Debit) | دائن (Credit) | 5 |

### 3. مسار المعالجة المالية الإلزامي (The Sacred Financial Pipeline)
يُحظر تماماً تحديث الأرصدة أو التقارير بمعزل عن المسار التالي:
`
Business Event (حدث تجاري: بيع، شراء، قبض، صرف)
       │
       ▼
Accounting Rule (القاعدة المحاسبية وتحديد الحسابات المتأثرة)
       │
       ▼
Journal Entry (إنشاء قيد اليومية المتزن: أسطر مدين ودائن)
       │
       ▼
General Ledger (ترحيل القيد لدفتر الأستاذ العام)
       │
       ▼
Account Balance (تحديث الرصيد التراكمي للحساب آلياً)
       │
       ▼
Financial Reports (ميزان المراجعة، قائمة الدخل، الميزانية العمومية)
`

## 4. 🛑 محظورات قطعية وممارسات ممنوعة (Forbidden Anti-Patterns)

1. **حظر القيد غير المتوازن (Unbalanced Entry Prohibition):**
   * يمنع منعاً باتاً حفظ أي قيد يومية إذا كان مجموع المدين != مجموع الدائن. أي فرق، حتى لو فلس أو سنت واحد، يجب أن يرفض العملية فوراً ويطلق خطأ صريحاً.
2. **حظر تعديل الأرصدة يدوياً (Direct Balance Mutation Prohibition):**
   * يمنع تشغيل استعلام UPDATE accounts SET balance = X أو current_balance = Y بشكل يدوي أو مباشر بدون قيد يومية رسمي مسجل ومرتبط.
3. **حظر استخدام الأرقام العائمة للأموال (No Floats for Money):**
   * يمنع استخدام أنواع FLOAT أو DOUBLE في تخزين أو حساب المبالغ المالية.
   * الالتزام التام بنوع Decimal في Python ونوع NUMERIC(18, 4) في PostgreSQL مع التقريب المالي المعتمد (ROUND_HALF_UP).
4. **حظر الحذف النهائي للبيانات المالية (No Hard Deletion):**
   * يمنع حذف أي قيد يومية أو سند معتمد باستخدام DELETE FROM.
   * الإلغاء أو التصحيح يتم فقط عبر **قيد عكسي متزن (Reversing Entry)** أو قيد تسوية (Adjusting Entry) مع توثيق سبب التعديل في سجل التدقيق (Audit Trail).
5. **حظر التعديل في الفترات المغلقة (Closed Period Immutability):**
   * يمنع إضافة أو تعديل أي قيد بتاريخ يقع ضمن فترة مالية تم إقفالها واعتماد ميزانيتها.
6. **إلزامية المعاملات الذرية (Atomic ACID Transactions):**
   * أي عملية مالية تتضمن أكثر من خطوة (مثل: إنشاء سند + تحديث قيد + تحديث ذمة عميل) يجب أن تنفذ داخل معاملة ذرية متكاملة؛ وفي حال فشل أي خطوة يتم التراجع الكامل (Rollback).

## 5. 📋 القواعد المحاسبية النموذجية للحركات الست الأساسية

### 1. بيع نقدي (Cash Sale):
- **المدين:** حـ/ الصندوق أو البنك (101 / 102)
- **الدائن:** حـ/ إيرادات المبيعات (401)
- **القاعدة:** $\text{Debit(Cash)} = \text{Credit(Sales)}$

### 2. بيع آجل (Credit Sale):
- **المدين:** حـ/ العملاء - المدينون (104)
- **الدائن:** حـ/ إيرادات المبيعات (401)
- **القاعدة:** $\text{Debit(Receivables)} = \text{Credit(Sales)}$

### 3. تحصيل دين عميل (Receipt on Account):
- **المدين:** حـ/ الصندوق أو البنك (101 / 102)
- **الدائن:** حـ/ العملاء - المدينون (104)
- **القاعدة:** $\text{Debit(Cash)} = \text{Credit(Receivables)}$

### 4. شراء بضاعة/أقمشة بالآجل (Credit Purchase):
- **المدين:** حـ/ المخزون (103) أو حـ/ مشتريات خامات (502)
- **الدائن:** حـ/ الموردين - الدائنون (201)
- **القاعدة:** $\text{Debit(Inventory/Purchases)} = \text{Credit(Payables)}$

### 5. سداد مستحقات مورد (Payment to Supplier):
- **المدين:** حـ/ الموردين - الدائنون (201)
- **الدائن:** حـ/ الصندوق أو البنك (101 / 102)
- **القاعدة:** $\text{Debit(Payables)} = \text{Credit(Cash)}$

### 6. مصروف تشغيلي نقدي (Cash Expense):
- **المدين:** حـ/ مصروفات تشغيلية / إيجار / رواتب (501 - 505)
- **الدائن:** حـ/ الصندوق أو البنك (101 / 102)
- **القاعدة:** $\text{Debit(Expense)} = \text{Credit(Cash)}$

## 6. 🧪 إرشادات وقواعد التحقق البرمجي (Verification Standards)
عند كتابة أو مراجعة أي كود محاسبي:
1. تحقق من أن كل عملية تستخدم Decimal(str(val)) بدقة عالية.
2. تحقق من أن كل قيد يحوي مصفوفة أسطر متزنة، وأن:
   \sum \text{debit} == \sum \text{credit}
3. تحقق من أن دفتر الأستاذ العام (General Ledger) يعكس القيود دون فقدان لأي طرف.
4. تحقق من ميزان المراجعة (Trial Balance): إجمالي الأرصدة المدينة = إجمالي الأرصدة الدائنة.
